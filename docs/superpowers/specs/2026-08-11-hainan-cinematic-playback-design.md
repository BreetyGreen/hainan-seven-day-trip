# 海南旅程电影式播放设计

## 目标

把现有海南七日地图升级为可自动播放的旅程叙事：页面首次进入后从武汉开始，路线逐段绘制，镜头跟随旅行者，每到一个真实地点展示对应活动并短暂停留，随后继续。用户可以暂停、继续和从头重播。

## 播放节奏

- 全程按 Day 1 到 Day 7、每天 `placeIds` 的既有顺序播放，不新增虚构地点。
- 首次进入并完成路线数据加载后延迟约 800ms 自动播放。
- 交通段持续约 1.2–2.8 秒；节点停留约 1.0–1.6 秒。全程目标时长约 55–75 秒。
- 每天开始时激活 D1–D7 进度节点并调整镜头；行进中旅行者图标沿真实 GeoJSON 路线移动；抵达时聚焦地点并显示活动卡。
- 播放完成后保留完整高亮路线并显示完成状态；“重播”清空播放轨迹并从武汉重新开始。

## 活动状态

地点动画只使用已有数据，并由地点类别映射：

- `transport`：交通，显示飞机/汽车流动效果。
- `food`：吃饭，显示餐食与蒸汽效果。
- `stay`：休息/入住，显示呼吸灯与休息效果。
- 其他真实景点：游玩，显示定位光环和探索效果。

活动卡展示 Day、时段、地点、活动类型、停留时长、推荐理由；有匹配的小红书实景图时才显示图片，没有匹配图时使用类别图形，不使用库存图。

## 技术结构

- `app/trip-playback.ts`：纯函数播放计划生成器。把 7 天地点和 9 条连续 GeoJSON 路段合并为按日计划，并将每个地点匹配到真实路线上的最近顺序坐标，输出地点停留阶段与交通阶段。
- `app/RouteMap.tsx`：Leaflet 播放状态机。静态全程继续使用一个 Canvas；播放轨迹使用独立 Canvas，只维护飞机和自驾两条多段折线；一个旅行者标记通过 `requestAnimationFrame` 移动。
- React 只在阶段切换和低频进度更新时渲染；每帧坐标、路线和镜头通过 Leaflet ref 更新，避免每帧 React 重渲染。
- 镜头在日切换和抵达时使用 `flyTo`，行进中使用低频 `panInside` 保持旅行者在安全视区，不持续强制居中。

## 交互与中断

- 播放按钮在“播放 / 暂停 / 继续”之间切换；重播按钮始终从 Day 1 开始。
- 用户选择顶部某一天时停止全程播放，回到现有按天地图；回到“全程”后不会重复自动启动，需点击播放或重播。
- 用户拖拽地图时自动暂停，避免镜头与手势争夺控制。
- 点击普通地点仍打开现有详细弹窗，播放卡不替代详情弹窗。

## 性能与无障碍

- 播放层最多两个 Canvas 折线和一个移动标记；路线坐标按段降采样，保留端点和真实路径形状。
- 镜头跟随最高约每 450ms 更新一次，React 播放进度最高约每 120ms 更新一次。
- `prefers-reduced-motion: reduce` 时不自动播放、不连续移动镜头；用户手动播放时按日跳转并直接呈现节点信息。
- 播放状态和抵达地点使用 `aria-live="polite"`，控制按钮包含明确状态文案。

## 验收标准

1. 首次进入后自动从 Day 1 武汉节点开始播放。
2. 真实路线会逐段出现，旅行者标记沿路线前进。
3. D1–D7 具有可见的完成、当前和未开始状态。
4. 每个 `placeIds` 节点都会触发一次活动卡，重复回到酒店也会触发休息节点。
5. 交通、游玩、吃饭、休息具有不同图标和动画。
6. 镜头在日切换、行进和抵达时跟随，但用户拖拽可暂停。
7. 播放、暂停、继续、重播和顶部按天筛选都能正常工作。
8. 现有地点详情弹窗、酒店侧栏和移动端布局不回退。
9. 减少动态模式不自动播放，并可理解完整行程。
